Schemas

The machine-readable half of the standard. Every schema lives at a canonical URL that doubles as its JSON Schema $id:

https://opengdd.org/schema/<layer>/v<minor>/<file>.schema.json

Today there is one layer, core, at v0.5. A schema URL is never repurposed: when a construct changes, the version segment changes with it, and superseded URLs keep serving what they always served. Corrections appear as errata at the same URL, and never silently change a validation outcome.

SchemaWhat it validates
manifest.schema.json The package manifest: identity, target, build contract, content collections, descriptor families.
direction.schema.json The art-direction block in machine form: pillars, mood, references, constraints, audit hooks.
opengdd-build.schema.json The manifest a finished build ships: builder, resolved tuning, acceptance outcomes, result hash.

Superseded

OpenGDD core v0.4 remains available at its permanent URLs: manifest.schema.json, direction.schema.json, and opengdd-build.schema.json.

Checking a whole package takes more than any JSON schema can express. That job belongs to the conformance validator, which builds on these schemas.
