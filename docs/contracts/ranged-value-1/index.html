What this contract covers

A bounded number with named thresholds: the decisions behind every health bar, stamina meter, heat gauge, or currency floor, written down once.

The pool holds one number, its value, with declared limits min and max. A limit constrains the value only as far as its own effect policy says; under unbounded it is a named landmark, not a limit.

The value changes only through deltas: signed numbers applied by single events. A delta applies as one step — the value before and the value after are observable, a partially applied value never is. The raw pre-correction value is not hidden: under raw-result the pool's own threshold tests read it, and a game may expose it as a declared observable.

Deltas come in two kinds. An effect is imposed: the pool is not asked, and the policy of the limit the delta would leave — at-max-effect above, at-min-effect below — decides what happens. A cost is voluntary: an actor proposes to spend a positive amount downward, and insufficient-cost decides whether the spend and its action proceed.

A threshold is a named value inside [min, max] with a direction. A crossing happens when one delta takes the value from not-reached to reached in that direction, where reached is defined by boundary-comparison.

A crossing is reported as a named event carrying the threshold id and the value before and after. What the game does with it is game prose; how often it fires is the row's own refire answer.

Questions it answers

5 decisions, grouped for reading

Thresholds and limits

boundary-comparison

When the value lands exactly on a line — a threshold, or min or max — does that count as reaching it?

Choose an option to explore what it means. Nothing will be saved.

Exploring: Inclusive

Landing exactly on the line counts. If a threshold sits at 25, dropping to exactly 25 reaches it; filling to exactly max counts as full.

Exact wording

A threshold is reached when the value is at or past it in the threshold's direction: for a rising threshold at t, value >= t; for a falling one, value <= t. A limit (min or max) is met when the value equals it.

Exploring: Exclusive

Exactly on the line is not there yet — only strictly past it counts. A value resting right on a threshold has not reached it.

Exact wording

A threshold or limit is reached only when the value is strictly past it in its direction: rising means value > t, falling means value < t. A value resting exactly on a threshold, min, or max has not reached it.

Additional context: Rare in practice, and it changes which values fire a threshold sitting exactly on min or max — answer the overshoot question with this one in mind.

Why this question matters

Every check in this contract asks whether a value has been reached; without an answer there are no defined crossings. In practice, counting the exact landing is near-universal.

threshold-checks-read

When a change overshoots min or max, do threshold checks read the number the player ends up seeing, or the raw result from before it was pulled back into range?

Choose an option to explore what it means. Nothing will be saved.

Exploring: Final value

Checks read the number the player sees. A hit that would land at −20 shows 0, and every threshold check reads that 0.

Exact wording

Apply the delta, bring the result into range as the limit's effect answer directs, and test every threshold against that final value. The value tested is always a value the pool holds.

Exploring: Raw result

Checks read the raw result first — that −20 — and only then does the value snap back into range. Rules can react to how far past the limit the hit went.

Exact wording

Apply the delta, test every threshold against the raw post-delta value even when it lies outside the range, then bring the value into range. The value tested may be a value the pool never holds.

Why this question matters

An overshooting change produces two candidate numbers to check — the raw result and the corrected one — and codebases routinely check both ways inside one game without noticing, so this question deliberately offers no default. The difference is visible: with exclusive counting and an empty-pool threshold at min, one order fires the empty event on an overshooting hit and the other never does.

Effects at the limits

at-max-effect

When a gain would push the value past max, what happens?

Choose an option to explore what it means. Nothing will be saved.

Exploring: Clamp

The value stops at max. The extra is thrown away — nothing is told about it, and nothing else happens.

Exact wording

The value saturates at max. The excess is discarded, reported to no one, and carries no further consequence from this contract; the event otherwise applies in full.

Exploring: Reject delta

The gain doesn't happen at all; the value stays put.

Exact wording

The delta is not applied at all and the value is unchanged. Whether the causing event has consequences elsewhere is outside this contract.

Exploring: Return remainder

The value fills to max, and the part that didn't fit is handed back to whatever caused it — yours to use, not silently lost.

Exact wording

The delta applies up to max, the value ends exactly at max, and the excess is reported back to the source of the causing event as a value. What the source does with it is game prose. The one observable difference from clamp: there the excess is destroyed and nobody is told; here the caller is handed it and becomes responsible for it.

Exploring: Unbounded

No ceiling. The value keeps climbing past max; max stays a marked line thresholds can sit on.

Exact wording

max does not constrain the value upward: the delta applies in full and the result is stored, even above max. max stays declared and citable — thresholds may sit at or below it and are tested normally — but it is a landmark, not a ceiling. at-min-effect is answered independently.

Why this question matters

The range is the mechanism: a pool with no answer for changes that would leave it is the silent-clamp hole this contract exists to close. A pool with no real ceiling answers unbounded — a recorded decision, not a silence.

When a loss would drag the value below min, what happens?

Exploring: Clamp

The value stops at min. The overkill is thrown away — nothing is told about it, and nothing else happens.

Exact wording

The value saturates at min. The excess is discarded, reported to no one, and carries no further consequence from this contract; the event otherwise applies in full.

Exploring: Reject delta

Spending

insufficient-cost

When something tries to spend more than the pool has left above min, what happens?

Choose an option to explore what it means. Nothing will be saved.

Exploring: Reject action

Can't afford it, can't do it. The action is refused and nothing is deducted.

Exact wording

The spend is rejected and the action it would have paid for does not occur. The value is unchanged and no threshold fires.

Exploring: Partial spend

The pool empties to min and reports how much it actually got. What a partly-paid action does is your call.

Exact wording

The value is set to min and the spend reports the amount actually spent: the headroom above min before the spend. What the action does with a partial spend is game prose; the contract fixes only the end state and the reported amount.

Exploring: Not applicable

Nothing in this game ever pays from this pool — every change is imposed on it.

Exact wording

This pool has no voluntary-spend verb: every change is an imposed effect. All cost templates are pruned.

Why this question matters

The one question that permits not-applicable: a pool nothing ever spends from is a smaller pool, not an underdetermined one. No default is offered — rejecting the action is the commonest answer, but partial spending is genuinely common too.

Collections

thresholds

Thresholds

The named thresholds this pool reports crossings for, each row deciding how often it fires. Rows live inline in the instance file or in a declared collection. An empty collection is legal: no threshold template expands and the pool reports no crossings.

FieldKindWhen it appearsMeaning
id string Required Stable name, unique in the collection; the id the crossing event carries.
value number Required Where the threshold sits; MUST lie within [min, max]. A row at min or max is how an empty-pool or full-pool event is declared — exactly where the landing and overshoot questions become observable together.
direction choice: rising, falling, both Required The direction of travel in which a crossing of this threshold fires.
refire choice: every-crossing, once Required every-crossing: fires each time it is crossed. once: fires the first time, then waits until it re-arms. Per-row because real pools mix both — progression thresholds fire once, continuous-state ones fire every time.
rearm choice: run-reset, declared-event Applies when row refire is Once. MUST be present exactly when refire is once. run-reset: the threshold re-arms at run reset and at no other time. declared-event: it re-arms when a game event named by this row occurs, and also at run reset.
rearm-event citation Applies when row rearm is Declared event. MUST be present exactly when rearm is declared-event: a citation to where this game's own prose declares the re-arming event, so the scope is never implied.

threshold-fires-once

Row.id fires once, then waits to re-arm

scenarioper thresholds row

Applies when row refire is Once.

Row.id fires once: across a cross, return, cross-again sequence it reports exactly one crossing — the first — and then waits. It re-arms Bind rearm phrase; once re-armed, the next qualifying Row.direction crossing reports once again. Reached means Bind reach phrase Row.value.

Test steps and diagnostics
Given

the Instance pool holding a value that has not reached the Row.id threshold at Row.value, with Row.id armed

When
  • Instance crosses Row.id in the Row.direction direction, returns to a value that has not reached Row.value, and crosses Row.id again in the Row.direction direction, with no re-arming occurrence in the sequence
Then
  • the Row.id crossing is reported exactly once over the whole sequence, on the first qualifying crossing
  • the second crossing reports nothing
  • the return leg reports nothing
  • after Row.id re-arms Bind rearm phrase, a further qualifying crossing reports once again

  • Instance-crossing-log
  • Instance-arm-state
