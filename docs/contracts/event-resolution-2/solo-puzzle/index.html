The contract that this adoption uses

This contract covers actions and events that happen at the same game moment. It decides their order, ties, interruptions, chain reactions, and refused actions. It also settles missing sources or targets, two removals reaching one target, simultaneous endings, and presentation delays. This contract does not cover individual effects, input buffering, clocks and pausing, displayed facts, or the simulation stages of each game update. The Input forgiveness contract covers input buffering. The Fact list contract covers displayed facts.

An action cannot happen exactly as proposed. What happens by default?

Choices for An action cannot happen exactly as proposed. What happens by default?
Supplied answer The refused attempt changes nothing. A tactics unit blocked by a closed gate keeps its stamina and its turn.

The refusal changes no game state, spends no cost, and advances no clock. Time already advancing independently may continue.
The refused attempt spends its cost and changes nothing else. A card refused after commitment still spends its mana.

The refusal applies the action's complete declared cost, produces none of the action's effects, and does not advance a clock because of the refusal.
The refused attempt moves time forward and spends no cost. A roguelike hero who walks into a wall still uses a turn.

The refusal advances one clock once, applies no cost, and produces none of the action's effects. Every case using this result cites the clock rule in its rejection-cases row.
The refused attempt spends its cost and moves time forward. A dungeon wand that fails uses one charge and one turn.

The refusal applies the complete declared cost and advances one clock once, but produces none of the action's effects. Every case using this result cites the clock rule in its rejection-cases row.
The action happens with a smaller result instead of failing. A factory machine on low power makes parts more slowly.

The proposal is accepted, not refused. The scale rule cited by its rejection-cases row scales the complete effect and cost, and the event continues through this lifecycle.
Every proposed action that this adoption covers is accepted. An arcade blaster always fires because ammunition and cooldown never refuse a shot.

No action governed by this adoption has a refusal branch.
Why this is asked

The attempt may fail, spend a resource, use time, or continue at a smaller scale. This answer is the default answer. A rejection-cases row can choose another result.

Two events of the same class are ready at the same moment. What decides which one goes first?

Choices for Two events of the same class are ready at the same moment. What decides which one goes first?
A named number that does not change decides the order. Strategy effects use priority first, and they use spawn number to decide a tie.

Every class with a visible tie has a row naming an integer the event holds when it enters the waiting set. The number may be the event's own or inherited from its source object, such as a relic's acquisition number or a minion's board position. Lower numbers resolve first. An optional second named integer decides between equal first numbers. When no second integer is named, equal first numbers cannot occur, or their order cannot change the result.
The event that entered the waiting set first goes first. Card effects triggered together resolve in the order they were added.

Earlier admission to the waiting set resolves first. Admission order is stable for the complete instant.
Grid position decides the order. Tied tactics units resolve row by row, starting from the map's first row. Inside one row, they resolve starting from the first column.

The grid cited by the class or rank-tie row defines what row and column mean. Its own first row resolves first; within that row, its own first column resolves first.
Positions resolve clockwise around a fixed center. Four boss hazards start from the direction the arena marks first.

The grid cited by the class or rank-tie row defines the center and the first direction. Clockwise angle continues the order, and the row's named stable index decides between events at an equal angle and distance.
Supplied answer No order can change the game result. Racing-game confetti bursts may update in either order because neither affects the race.

No event in the class observes another event in the same class during the instant, and every permitted execution order produces the same game state and player-facing result. This includes the case where two such events cannot arise together.
A declared random draw decides the order. Two creatures with equal speed roll to see which acts first.

Each affected class has a within-class-rules row citing the random rule and its complete draw procedure. The result may vary between runs; the cited rule, not container order, selects it.
Why this is asked

A class is one kind of event in your event-classes list. The rank orders classes. It does not order two events of one class. Their order can change targets, rewards, and later chains.

Choices for A win and a loss happen at the same moment. Which ending does the game record?
Only the loss is recorded. An arena hero who defeats the boss while reaching zero health loses the run.

The lifecycle records only the loss, regardless of event rank or the order in which the two ending conditions were detected.
Only the win is recorded. A racing driver who crosses the finish line while crashing still wins.

The lifecycle records only the win, regardless of event rank or the order in which the two ending conditions were detected.
Both endings are recorded. A card duel in which both heroes reach zero health records a shared defeat and a completed victory condition.

Can an animation or sound delay an event, and can another event pass it?

Asked when
the presentation driven events list has at least one row.
If not asked
No animation or sound delays an event or changes the order of events.
Choices for Can an animation or sound delay an event, and can another event pass it?
Presentation never changes game timing or order. An attack resolves at game time even when its animation runs early or late.

No named event waits for presentation. The rows record that the game considered these events and declared that they do not wait. An adoption with no rows makes no such declaration. This question is then not asked, and no animation or sound delays an event or changes the order of events.
The listed events may wait for their animation or sound. Every later event waits until they finish. A card attack resolves after its animation, and later effects keep their order.

Only events named by presentation-driven-events wait for a cue of their own. Every event behind a held event in the order waits with it, so the delay cannot let a later event resolve first.
The listed events may wait for their animation or sound. Later events do not wait for them. A fighting-game cinematic can finish after a later poison pulse has already resolved.

Only events named by presentation-driven-events may wait. A later eligible event may resolve before a delayed event, and the delayed event keeps its original payload.
Why this is asked

A visual delay and a rules delay are different decisions. The answer decides whether only time changes or order changes too.

Two events would each remove the same target at this moment. What happens to the second one?

Asked when
the same target cases list has at least one row, or the same target exceptions list has at least one row.
If not asked
No two events in this adoption can each remove the same target at one instant.
Choices for Two events would each remove the same target at this moment. What happens to the second one?
Only the first event affects the target. Two tactics arrows reach the last enemy, and the later arrow finds no target.

The first ordered event applies to the target and removes it. Every later event in the collision applies nothing to that target; its cost and carrier follow their own game rules. Every class that can supply two events to such a collision has a visible order. This means that its within-class-rules row, its rank-ties row, or the default answer to within-class-order gives an order other than no-visible-order.
Every event applies, but the target is removed once. Two arena hits both count before one enemy defeat is recorded.

All events in the collision apply to the target in order. Removal is deferred until the collision group ends and is recorded once.
Every event applies, and each event records its own removal result. Two arcade lasers can each award a break bonus from one target.

Every event in the collision applies in order and records its own declared removal consequence, even after an earlier event recorded one.
Why this is asked

The second event may vanish, still count, or create another ending. This answer is the default answer. A same-target-exceptions row can choose another result for its target kind.

An event happening now causes another event due at this moment. When does the new event resolve?

Asked when
the caused event kinds list has at least one row.
If not asked
No non-interrupt event in this adoption causes another event due at the same instant.
Choices for An event happening now causes another event due at this moment. When does the new event resolve?
The new event resolves inside the event that caused it. A card's defeat effect draws a replacement before the next waiting card effect.

The caused event finishes inside the event that caused it, before the next waiting event. Every caused-event row cites a finite chain bound.
The new event joins its normal place in the current order. An arena enemy activated early can attack later in the same moment.

The caused event resolves in its declared class's place, this instant or the next. Every caused-event row cites a finite chain bound.

Why this is asked

A chain can continue immediately, join the normal order, or wait for the next game moment.

An interrupt can stop or replace an event that is already happening. When does the interrupt take effect?

Asked when
the interrupts list has at least one row.
If not asked
No event in this adoption stops or replaces another event once it has been selected to resolve, at any point including before its first effect.
Choices for An interrupt can stop or replace an event that is already happening. When does the interrupt take effect?
The interrupt takes effect before the next effect of the current event. A card secret counters a spell before its damage applies.

At each declared effect boundary, a valid interrupt resolves before the next effect of the active event. The interrupt row then stops or replaces the active event.
The current effect finishes before the interrupt takes effect. A parry accepts the sword's contact, prevents the remaining damage, and replaces it with stagger.

The active effect commits first. A valid interrupt then resolves at the following declared boundary and stops or replaces every remaining effect of the active event.
The interrupt joins the normal event order. A factory emergency stop waits for the safety rank, then cancels later machine work.

The interrupt joins this instant when its class is current or has not passed, and otherwise joins the next instant. When it joins the next instant, the active event finishes unchanged in this one and the interrupt stops or replaces only events of its active class that are still waiting or active when it resolves. It remains an interrupt creation path, so the caused-events answer does not govern it.
Why this is asked

An interrupt needs a fixed entry point before it can stop or replace the event already in progress.

An event loses the source or target it needs. What happens by default?

Asked when
the orphan cases list has at least one row.
If not asked
No event in this adoption can lose its required source or target while waiting or resolving.
Choices for An event loses the source or target it needs. What happens by default?
The event still resolves with the state that remains. A card's queued effect continues after its minion leaves play.

The event keeps its captured payload. A missing source or target is unavailable, effects that require it are skipped, and every independent effect still resolves. This is the default answer unless the orphan-cases row chooses another result.
The event is canceled. A homing shot disappears when its only target leaves play before impact.

The event produces no further effect after the required source or target becomes unavailable. Costs already committed are not restored by this contract. This is the default answer unless the orphan-cases row chooses another result.
Why this is asked

A queued card effect or tactics shot can still be waiting after its source or target is gone. The result must not depend on which object the game removed first.
