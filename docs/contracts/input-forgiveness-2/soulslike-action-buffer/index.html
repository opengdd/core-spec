The contract that this adoption uses

This contract covers inputs accepted just before the game allows the action, just after it stops allowing it, or near a target moment such as a beat or impact. It records which game actions receive that help, what arms each case (makes it ready to accept or save an input), and when a saved action fires (becomes ready for the game to try). This contract does not cover physical controls, ordinary action rules, or small position corrections such as corner correction. The Control options contract covers physical controls.

Questions

Several inputs that receive this help become ready at the same moment. Which ones does the game try?

Asked when
the late input windows list has at least one row, or the input buffers list has at least one row, or the target moment windows list has at least one row.
If not asked
No forgiveness row can make an input ready.
Choices for Several inputs that receive this help become ready at the same moment. Which ones does the game try?
The game tries every helped input that becomes ready. A twin-stick hero may dodge and shoot at the same moment.

Every ready forgiven input is submitted once as an action proposal. Event resolution owns their order and the game rules may still refuse incompatible actions.
Supplied answer The game tries only one ready input. A fixed priority in your game's rules chooses it. A farm tool may water, and not plant, when both become ready.

Exactly one ready forgiven input is submitted. The matching competition-rules row supplies one total priority over every input that can be ready in that situation.
Two helped inputs can never become ready at the same moment. A one-button rhythm lane has at most one note action at a beat.

The adoption guarantees that no reachable game state presents two ready forgiven inputs at one moment. Reaching such a state invalidates the design claim.
Why this is asked

A landing, beat, or recovery end can make several helped inputs ready. The game must decide which ones to try.

forgiveness-vocabulary-and-openness

input forgiveness uses the mapped action input and cited openness

scenarioonce

Applies to soulslike-action-buffer.

For a declared row, an action input is the event that the game receives after Control options maps a physical control; device identity does not change settlement. Ordinary permission is the action's legal state before forgiveness, and a press uses the edge named by the cited action rule. Openness comes from the agreeing Timed window adoption where one exists, otherwise from the cited Fixed timing rule. Where this adoption has no row in a row set, this test checks nothing for that row set.

Test steps and diagnostics
Given

a physical control mapped through Control options to an action input that reaches a declared forgiveness row

When
  • the row reads ordinary permission, its input edge, and whether its window instance is open
Then
  • the action input is the event that the game receives after mapping, independent of physical device identity
  • ordinary permission is the action's legal state before forgiveness
  • the press arrives on the edge named by the cited action rule, including a release edge where that rule names one
  • openness comes from the agreeing Timed window adoption where one exists and otherwise from the row's cited Fixed timing rule
  • an accepted late or target input, or a saved press whose firing event has arrived, is one ready forgiven input
  • where this adoption has no row in a row set, this test checks nothing for that row set

empty-row-families-create-no-forgiveness

empty row sets create no forgiveness state

scenarioonce

Applies to soulslike-action-buffer.

An empty late-input-windows set keeps no action available after ordinary permission ends; an empty input-buffers set means no early press waits for an action to become ordinarily permitted; an empty target-moment-windows set forgives no input near a target moment; and an empty competition-rules set declares no priority. Where a named set has a row, this test checks nothing for that set. If all three forgiveness row sets are empty, no forgiveness row can make an input ready and the competition-rules description allows no competition rows; any competition row then makes the adoption invalid, and this test fails. Where any forgiveness row set has a row, this test checks nothing for that last case.

Test steps and diagnostics
Given

the soulslike-action-buffer adoption document and its row sets

When
  • each empty row set's declared consequence is read
Then
  • where late-input-windows is empty, no action remains available through forgiveness after ordinary permission ends; where a row exists, this test checks nothing in this line
  • where input-buffers is empty, no early press waits for an action to become ordinarily permitted; where a row exists, this test checks nothing in this line
  • where target-moment-windows is empty, no input is forgiven because it arrives near a target moment; where a row exists, this test checks nothing in this line
  • where competition-rules is empty, no competition priority rule is declared; where a row exists, this test checks nothing in this line
  • where all three forgiveness row sets are empty, no forgiveness row can make an input ready; where any of them has a row, this test checks nothing in this line
  • where all three forgiveness row sets are empty, competition-rules has no rows; any row in it then makes the adoption invalid, and this test fails; where any forgiveness row set has a row, this test checks nothing in this line

receipt-family-order

target, late, buffer, and ordinary receipt keep their fixed order

scenarioonce

Applies to soulslike-action-buffer.

A receipt evaluates target rows first whether ordinary permission exists or not. If none accepts and permission exists, it submits the ordinary attempt without forgiveness. Without permission, late rows run next and a buffer captures only if neither a target row nor a late row accepts. Where this adoption has no row in a row set, this test checks nothing for that row set.

Test steps and diagnostics
Given

action-input receipts that exercise every forgiveness row set in which the soulslike-action-buffer adoption has a row

When
  • ordinary permission is present in one receipt and absent in another
Then
  • every matching target row is evaluated regardless of ordinary permission before any late or buffer row
  • ordinary permission prevents late and buffer evaluation but does not prevent target evaluation
  • if no target row accepts and ordinary permission exists, the ordinary attempt is submitted without forgiveness and the receipt ends
  • with no ordinary permission, late rows run before buffer rows, and a buffer captures only if neither a target row nor a late row accepts
  • where this adoption has no row in a row set, this test checks nothing for that row set

buffer-captures-one-press · dodge-during-recovery

Applies to the dodge-during-recovery row.

While combat.dodge-input-during-recovery holds, dodge-during-recovery stores one qualifying press of an action this row covers (dodge), its input moment, and one instance under combat.dodge-recovery-buffer.
