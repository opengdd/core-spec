Known limitations

This document ships with OpenGDD v0.x. An honest format states what it cannot yet do. The limits below come from development rounds that pressed the format against real games, both original designs written for the purpose and well-known published games expressed after the fact. "Expressible" never means "uniformly machine-discoverable or portably machine-verifiable," and this page keeps those apart.

Deliberately out of scope#

OpenGDD v0.x does not define:

  • multiplayer session, delivery, and networking behavior;
  • rendered-capture certification for 3D renderers — a web-3d package validates, and a build of one can certify when its acceptance tests need only logic and state observations, but no standardized sampling recipe exists yet for photographing a 3D renderer's output;
  • binary asset pipelines;
  • localization structure;
  • monetization design beyond attribution;
  • a registry API; or
  • target families beyond web delivery (web-2d, web-3d).

The multiplayer exclusion was pressed directly by expressing a well-known social-deduction game (Among Us). It held, but proved thin: roughly three quarters of that game's normative rules already express as ordinary deterministic rules. A future profile would mostly need to standardize session membership, authority, state delivery, and private-view non-leakage; none of that is standardized or certified in v0.x. Human testimony, belief, deception, and trust remain permanently outside machine certification. A separate test (Inscryption) confirmed that authentic host-filesystem, save-byte, achievement, and recording integration is not standardized for the v0.x web target, even though simulated in-fiction versions of those things are ordinary game state.

In-scope constructs not yet standardized#

These are not claims that any game is unbuildable. They are places where a package today needs local prose conventions or bespoke verification adapters that independent tools cannot infer from OpenGDD alone. Each has a queued proposal; see how the format evolves.

  • Numeric authority tiers. No formal boundary yet between balance tunables, fixed structural constants, per-content certified facts, and verification parameters.
  • Typed validity conditions. Per-key ranges cannot state ordering between keys, derived equalities, registry counts, or bounds computed from other bounds.
  • Structured-content authority. JSON data collections have no standard way to inherit or override the chapter authority levels.
  • Richer test kinds. The build plan names scenario acceptance tests; bounded properties, complete state-space searches, static spec/content lint, and replay fixtures with tolerances are used in practice but not yet all first-class.
  • PRNG addressing. No standard grammar for naming independent random streams or nested variable-count events portably.
  • Machine-readable personalization. Numeric personalization has no machine-readable target, operation, and bound policy.
  • Authored-puzzle solver interface. Authored puzzles have a normative layout encoding, but the solver-interface contract that would let an independent tool certify solvability is still open, and the evidence says the current draft must widen before locking.

Edge boundaries#

Statements about what v0.x standardizes and certifies, not about what is expressible in principle. Each was established by expressing a published game that lives on the edge in question.

What a player knows is not a state predicate#

Claims about what a player knows, perceives, believes, or can infer (the heart of Outer Wilds or Return of the Obra Dinn) are outside the machine-certification surface, and converting them into invented authoritative flags would be dishonest. The corresponding operational claims are expressible and certifiable: route reachability, causally inert log state, elimination necessity, batch-validation behavior. v0.x certifies the operational witness, never the epistemic claim.

Author-declared rule mechanics work; open mutation is out#

A finite rule universe derived at runtime (Baba Is You), a closed ruleset replacement (Inscryption), and activation of predeclared rule hooks (Frostpunk) are all expressible today, though a shared ruleset-state construct is still queued. Runtime creation of rule vocabulary the author never declared remains not standardized and not certified.

Bounded simulation certifies; simulation grain does not#

Continuous physics and emergent systems are not wholesale outside the format: fixed observable envelopes can certify motion without mandating an integrator, and bounded agent, hazard, and history-readout properties can be certified even for deep simulations (Dwarf Fortress). Two honest boundaries stand. First, a category gap: "the simulation produces a good story" is not a state predicate, and a package should decline proxy oracles that would certify the proxy instead. Second, the one genuine break found so far (Noita): material outcomes below the declared observable envelope stay player-observable, and pinning them would promote simulation grain into fixed architecture, which the format does not license. Sub-envelope outcomes are not standardized or certified in v0.x. A macroscopic material-envelope profile survives this break and was corroborated from the structural side (Teardown); it is queued.

Mixed time regimes express; portable verification is the gap#

One shared state moving through real time, tactical pause, discrete resolution, and strategic time (FTL; XCOM 2 supplies the inverse nesting) expresses today in prose and per-game content. What v0.x does not yet standardize is the reusable clocks block and freeze invariant an independent tool would need to verify the cross-regime seam without learning a bespoke harness. That construct is queued. Two adjacent needs stay outside it, each waiting on more evidence: nested interrupt/reaction-queue traces, and atomic regime-transition transactions.

Authoring lessons the format cannot absorb#

OpenGDD cannot compensate for a package that leaves its own rules contradictory or its evidence incomplete. Four lessons from the development rounds are worth stating normatively:

  1. Specify outcomes, not architecture. The valid requirement is the observable result: tests run headlessly, replay bounds hold, runtime values match the resolved data. Internal organization is the builder's craft.
  2. A fixture needs an input and a target. A tolerance without a recorded input, schedule, and expected observation certifies nothing. A fixture is certifying only when its input, expected observations, tolerances, and diagnostics are all present.
  3. Do not create a second authority channel. A local field whose values duplicate the authority levels, without being recognized by them, silently redefines Fixed. Declare data-collection authority in chapter prose until the standardized member exists.
  4. Do not restate tuning values in normative prose. Prose states formulas and key bindings; literal numbers in prose must be non-normative or generated from the authoritative data.

Beyond these, ordinary spec defects — contradictory authored facts, unreachable test premises, misclassified authority — are caught by review, not by any format primitive. Publication requires semantic review, reachable test setups, reference closure, and successful fixture replay in addition to schema validation.

Art direction: what transmits, and what does not yet#

The art-direction block is normative in v0.5, and its transmission has been measured rather than assumed. What the evidence shows so far:

  • Palette transmits machine-exactly, and shape language transmits well, from text-only direction.
  • Continuous material feel under-carries. Decomposable graphic features (stitches, edge treatments, shadows) arrive from reference imagery; fiber, translucency, and wet or matte sheen did not reliably arrive from text or imagery in any tested build, in stills or in motion. Whether this is a notation gap or a current limit of the building agents is undetermined, and the format does not pretend otherwise.
  • Personalized direction is unspecified. How player-selected presentation composes with palette-role semantics is undesigned.
  • Not every pinned surface has an evidence path. Pins carry evidence through certified tuning keys, fixture-backed tests, and declared audit hooks; an exact surface none of those can evidence (an exact texture, say) has no certification path yet.

Audio#

The specification's audio chapter is a draft and non-normative in v0.5. Audio direction can be written and carried mechanically with the same descriptors as visual direction, and it is fenced off from certification: no audio claim is judged or certified in v0.x. This is an honest limitation, not an oversight; the chapter is expected to become normative once the judgment protocol for it is trustworthy.
