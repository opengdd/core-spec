Personalization

Opt-in: add this when your game needs it.

Personalization lets you ask the builder, the person, team, studio, AI system, or combination that turns your package into a game, a question for one particular build. An answer can set shared tuning numbers, give the builder creative instruction, or do both. Every question has a default. Write question ids as lowercase words joined by underscores or hyphens.

personalization.json, the questions file

{
  "questions": [
    {
      "id": "wave_pressure",
      "prompt": "How intense should enemy waves be?",
      "type": "choice",
      "default": "steady",
      "options": [
        {
          "id": "calm",
          "label": "Calm",
          "sets": { "wave.gap_seconds": 24 }
        },
        {
          "id": "steady",
          "label": "Steady",
          "sets": { "wave.gap_seconds": 14 }
        }
      ]
    },
    {
      "id": "warning_time",
      "prompt": "How many seconds before a wave should the horn sound?",
      "type": "number",
      "default": 3,
      "sets": "wave.warning_seconds"
    },
    {
      "id": "wave_mood",
      "prompt": "How should the quiet between waves feel?",
      "type": "text",
      "default": "Tense, with distant movement but no music"
    }
  ]
}

On a choice option, sets is a map of numbers; on a number question, sets is the one key the answer fills. The builder chooses calm or steady for the first question. The second answer fills wave.warning_seconds. A text answer is free; the builder reads it and decides.

A build record is the builder's JSON report of what was built. Only a number with a range in tuning.json can be named by sets. Every number written by a choice option must sit inside that range; otherwise, the validator refuses the package. A number question's default must sit inside the range too. If the builder supplies a number answer outside the range, that answer is refused and the build record fails.

Questions are applied in their listed order. A later question may set a number an earlier one set; the later answer wins. The build record stores every answer, including defaults, and every tuning number as it stands after the answers are applied. This makes the numeric result repeatable while leaving creative answers open to the builder's judgment.

A choice option or number question without sets records creative instruction only. Personalization is not for choices made during play. Difficulty settings and upgrades selected by the player belong to the game's mechanics.

The authority chapter shows how a > PERSONALIZATION: tag connects a prose section to a question.

Full rules: OpenGDD specification, §5.
