Contracts

Opt-in: add this when your game needs it.

A contract provides reusable questions, values, and tests for a familiar game system, such as a health pool or a strategy-game camera. Adopt the contract and record this game's answers.

contracts/stamina.json, one adopted contract

{
  "format": "opengdd-contract-instance-1",
  "instance": "stamina",
  "about": "Stamina powers sprinting and dodging. Drain rates and refill sources stay in this game's chapters.",
  "core": {
    …
  },
  "surface": {
    "answers": {
      "at-min-effect": "clamp"
    },
    "knobs": {
      "min": { "value": 0, "unit": "stamina-points" },
      "max": { "value": 100, "unit": "stamina-points" }
    }
  }
}

The file has two parts:

  • the core declares the system, its questions, and reusable acceptance-test patterns. Copy the chosen core unchanged.
  • the surface records this game's answers. One line per question, plus one value per knob, which is a number defined by the core.

This excerpt shows one answer and two knobs. A complete surface answers every question that applies. format identifies the kind of file. instance is this game's name for the adopted contract and matches the filename.

The core asks what happens when stamina would fall below its minimum. This game answers clamp, so the value stops at the minimum. Every applicable question gets one answer.

The about line explains how this game uses stamina. Game-specific rules, such as which actions drain it, remain in your chapters.

When the core includes test templates, the authoring tool generates their acceptance tests in the build plan. After changing an answer, regenerate the tests instead of editing them by hand.

Browse the contracts catalogue to compare the questions and answers before adopting one.

Full rules: OpenGDD specification, §10.
