1. The shape of a spec

Your whole design fits in one folder, and you can hand that folder to anyone. A spec is one folder that holds the whole design at once.

a spec folder

my-dungeon-crawler/
  manifest.json       what this is, and what to build from
  tuning.json         the numbers
  01-overview.md      the pitch, and how the game should feel
  02-mechanics.md     the rules
  03-content.md       the game's content in lists
  04-presentation.md  art direction, and the feel of it
  05-build-plan.md    phases, and the tests a build has to pass
  06-traps.md         a chapter of your own

The Markdown chapters carry the design: creative prose you write to describe the game. The JSON files carry your game's data and can be validated.

  • The five numbered names are fixed. A builder opens them by name.
  • 03-content.md and 04-presentation.md are optional.
  • Past those five, add chapters of your own and name them however you like.

A builder reads manifest.json first, then the files it points at.

manifest.json, complete

{
  "opengdd": "0.5",
  "id": "my-dungeon-crawler",
  "version": "0.1.0",
  "title": "My Dungeon Crawler",
  "designer": { "name": "You" },
  "target": { "platform": "web-2d", "genre": "dungeon crawler" },
  "build": {
    "chapters": ["01-overview.md", "02-mechanics.md", "03-content.md",
                 "04-presentation.md", "06-traps.md"],
    "plan": "05-build-plan.md",
    "tuning": "tuning.json"
  }
}

The top block is identity, target says what kind of game this is, and build names the files to read.

Nothing else is hiding. No project file, no build system, nothing to install. The chapters are ordinary Markdown, so any editor you already write in will do.

The authoring tool creates this skeleton and checks that it stays whole.
