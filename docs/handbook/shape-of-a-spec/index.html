The shape of a spec

Required: every spec has this.

A spec is one folder containing the complete design. You can give that folder directly to a builder.

a spec folder

my-dungeon-crawler/
  manifest.json       what this is, and what to build from
  tuning.json         the numbers
  01-overview.md      the pitch, and how the game should feel
  02-mechanics.md     the rules
  03-content.md       prose about the game's content
  04-presentation.md  art direction and presentation
  05-build-plan.md    phases, and the tests a build has to pass
  06-traps.md         a chapter of your own

The Markdown chapters describe the game in prose. The JSON files store structured data that can be validated.

  • The five numbered filenames are standard. A builder opens them by name.
  • 03-content.md and 04-presentation.md are optional.
  • Past those five, add chapters of your own and name them however you like. Names numbered 06 and higher are reserved for your chapters. Future standard files will have unnumbered names.

The five required files can describe a complete game. Add opt-in files and folders only when your design uses them.

A builder reads manifest.json first, then the standard files and every additional file listed there.

manifest.json, complete

{
  "opengdd": "0.6",
  "id": "my-dungeon-crawler",
  "version": "0.1.0",
  "title": "My Dungeon Crawler",
  "designer": { "name": "You" },
  "target": { "platform": "web-2d", "genre": "dungeon crawler" },
  "build": {
    "chapters": ["01-overview.md", "02-mechanics.md", "03-content.md",
                 "04-presentation.md", "06-traps.md"]
  }
}

opengdd selects the format version. id, version, title, and designer identify the package. target says what kind of game to build, and build.chapters gives the reading order for your prose. The build plan and tuning file already have standard names, so the manifest does not repeat their paths.

These are ordinary Markdown and JSON files, independent of any engine or build system. The authoring tool can create the folder and keep its names and references connected.

In later JSON examples, … means that unrelated fields were left out.

Full rules: OpenGDD specification, §1 and §3.
