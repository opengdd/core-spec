4. Identifiers

Every value in your game can carry a name. An identifier is that name: define the value once, cite the name everywhere you mean it. You write the name in backticks, right there in the sentence.

In a mechanics chapter:

A dash costs stamina.dash_cost, and cannot start when the bar holds less than that.

tuning.json, the numbers file

{
  "tunables": {
    "stamina.dash_cost": 25
  }
}

The sentence never states the cost; the file holds it. That name in your prose is a reference to a number you can change in a data file, instead of searching through your paragraphs for it. There is more to this convenient pattern, and its full power is the tuning chapter's subject.

Citations follow one rule: a bare dotted name in backticks is a tuning key, unless it opens with a segment the format keeps for a mechanism of its own, such as mood or meta, and every other kind of reference wears its kind in front, state:, content:, or descriptor:, each introducing itself in the chapter that owns it.

The authoring tool carries the bookkeeping so you stay in the writing. An identifier with no value in the data file shows up as a warning, and the tool offers to create the entry.

Full rules: Reference §4 and §8.
