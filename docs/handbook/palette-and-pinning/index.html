Palette & pinning

Opt-in: add this when your game needs it.

A palette records colors used by the game's visual direction. It lives in manifest.json and can contain unnamed colors or colors with stable names.

manifest.json, beside your mood entries

{
  …
  "palette": {
    "cellar.lantern": ["#1A1B2E", "#2E3450", { "flame": "#E8A13C" }]
  }
}

A value such as #E8A13C is a six-digit hex color. A palette key names the complete set. Here palette.cellar.lantern refers to all three colors, while palette.cellar.lantern.flame refers only to the named flame color. Write either reference in backticks in your prose.

Add a color constraint when a particular color needs a measurable limit.

direction.json, under constraints

{
  …
  "constraints": {
    "colors": {
      "lantern-flame": {
        "color": "palette:cellar.lantern.flame",
        "tolerance": 14,
        "scope": {
          "applies_to": "the lantern the player carries",
          "states": ["in-play"],
          "sampling": "exhaustive"
        }
      }
    }
  }
}

The constraint refers to the named palette color instead of repeating its hex value. tolerance is the permitted difference in perceived color. A tolerance of 0 requires the exact color; 14 permits nearby shades. scope states which object is checked and when. An acceptance test checks the constraint. Here states is a free-form list of situations in which the color rule applies, not a state:number: runtime value. sampling: exhaustive asks the test to inspect every applicable instance.

Every constraint needs a covering scenario or property test. That test names this one as constraints.colors.lantern-flame in its direction_claims; it does not repeat the color, tolerance, or scope.

How precise to be is your choice, color by color. The format names three levels:

  • described: prose, no measurement. Most direction stays here.
  • bounded: a color with a tolerance, like the 14 above.
  • exact: tolerance: 0. A build reproduces the six digits throughout the declared scope.

An exact constraint is a color pin. Use one only when reproducing that specific color is required.

Full rules: OpenGDD specification, §3, §4, §6, §8a, §9.5, and §9.8.
