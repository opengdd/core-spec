Art direction

Opt-in: add this when your game needs it.

Presentation prose is enough for many games. Add structured art direction when a build must preserve visual ideas while leaving room for interpretation. It uses three connected pieces.

First, manifest.json points to the direction file:

{
  "build": {
    "chapters": ["01-overview.md", "02-mechanics.md", "04-presentation.md"],
    "direction": "direction.json"
  }
}

Second, a direction block opens 04-presentation.md and cites the claims the builder should read:

> DELEGATED: presentation-direction

PILLARS:
- `pillars.white-on-white-still-reads`

MUST-KEEP:
- `must_keep.the-rope-stays-legible`

Third, direction.json holds those claims and the details needed to review them:

{
  "pillars": {
    "white-on-white-still-reads": {
      "statement": "Snow reads against snow: depth comes from shadow and edge, never from tinting the ground another color.",
      "viewing": "climb-camera",
      "tie_break_order": 1
    },
    …
  },
  "must_keep": {
    "the-rope-stays-legible": {
      "statement": "The rope between climbers stays visible in every weather, and its slack reads at a glance.",
      "may_vary": ["rope color and material", "falling snow", "HUD styling"],
      "viewing": "climb-camera"
    }
  },
  …
}

A pillar is a visual principle used to review the build. A must_keep entry names something every build preserves, while may_vary names related choices left to the builder. A viewing context says where a reviewer should inspect each claim, such as the normal climbing camera.

The direction block cites these entries instead of repeating them. The manifest pointer, prose block, and JSON file appear together; leaving one out is a validation error.

OpenGDD can also define mood, references, negative direction, and measurable constraints. A mood descriptor lives in manifest.json; when used in structured art direction, direction.json connects it to a viewing context. The palette and pinning chapter shows the measurable path for color.

Full rules: OpenGDD specification, §8a and §9.
