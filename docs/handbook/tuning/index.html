Tuning

Required: every spec has this.

Shared gameplay numbers that a build needs to read as data live in tuning.json, grouped into two categories: tunables and constants.

tuning.json, the numbers file

{
  "tunables": {
    "boost.duration_seconds": 1.5,
    "drift.grip": 0.62
  },
  "constants": {
    "race.lap_count": 3
  },
  "meta": {
    "boost.duration_seconds": { "range": [0.5, 2.5] }
  }
}

The two categories:

  • a tunable is a value you expect to retune while balancing;
  • a constant helps define the game itself. Changing one is a design change, not a rebalance.

This game always has three laps. Boost duration can change during balancing.

A number belonging to one collection record stays in that record. Test inputs stay with their acceptance test, and adopted contracts keep their knobs in the contract surface.

meta.range records the allowed values for a tunable. Here boost duration can be retuned from 0.5 to 2.5 seconds. Validation rejects a value outside that range.

Full rules: OpenGDD specification, §4.
